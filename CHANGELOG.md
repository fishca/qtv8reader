# История изменений

## [0.13.1] — 2026-11-26

### Исправлено

- Вывод инструментов тестовой базы переведён в UTF-8 общим модулем
  `tools/console_utf8.py`: на англоязычном Windows (cp1252) печать
  кириллицы в трубу или файл падала с `UnicodeEncodeError` — команда
  кончалась ошибкой при уже пройденной проверке. В 0.13.0 так был починен
  только гейт `control_fixtures`; теперь хелпер общий у всех десяти
  инструментов (`control_base`, `control_compare`, `control_fixture_check`,
  `control_matrix`, `control_refs`, `control_vocab`, `form_view_measure`,
  `form_view_probe`, `form_view_flaky_serve`, `form_xml_compare`).
- Признак `isatty()` для этого не годится: поток, отданный в `DEVNULL`,
  на Windows отвечает «да», и первая версия правки оставляла cp1252 — на этом
  падал сервер раздачи (`form_view_measure.py serve`), который запускает
  `control_compare.py`. Теперь поток переводится в UTF-8 всегда: для консоли
  на Windows это и так UTF-8 через консольный API, там ничего не меняется.

### Тесты

- `tools_utf8` в `ctest`: справка гейта `control_fixture_check.py` должна
  печататься при `PYTHONIOENCODING=cp1252`. Сторож на то, что вывод
  инструментов остаётся в UTF-8 при любой локали, — на обеих платформах.

## [0.13.0] — 2026-11-26

### Добавлено

- Тестовая база контролов управляемых форм: конфигурация «Контролы
  управляемых форм» с тринадцатью формами — `ПоляВвода`, `Надписи`,
  `Группы`, `Кнопки`, `ГруппаКнопок`, `Страницы`, `Таблица`, `Заголовок`,
  `КоманднаяПанель`, `Меню`, `Картинки`, `Колонки`, `Переключатели`.
  В репозитории лежат спецификация, скелет конфигурации, выгрузка, контейнер,
  эталоны из конфигуратора и бюджет расхождений (`tests/fixtures/controlbase`);
  как устроено — в [docs/control-test-base.md](docs/control-test-base.md).
- Инструменты тестовой базы: `control_base.py` (сборка базы и контейнера
  с обратным дампом), `control_refs.py` (съёмка эталонов из конфигуратора),
  `control_compare.py` (пиксельная сверка), `control_fixture_check.py`
  (гейт модели против `Form.xml`), `control_matrix.py` (матрица покрытия),
  `control_vocab.py` (словарь тегов и свойств по корпусу БП),
  `form_view_probe.py` (геометрия живого DOM), `form_view_flaky_serve.py`
  (подставной сервер с 500 на первый запрос картинки).
- Пиксельная сверка делит расхождение на **структурное** и **текстовое**:
  зоны текста берутся из прямоугольников текстовых узлов живого DOM, значений
  и плейсхолдеров полей (±1 px на субпиксельный сдвиг глифов), а не из маски
  «чернил» эталона. Бюджет каждой формы — `baseline.json`;
  `control_compare.py --all --check` падает при выходе за бюджет,
  `--update-baseline` фиксирует текущий уровень.
- Тест `control_fixtures` в `ctest`: JSON-модель каждой формы фикстуры
  сравнивается с её `Ext/Form.xml` — теги, имена, порядок и значения свойств.
  Работает без 1С и без Chrome.
- Своя командная панель таблицы значений: модель отдаёт узлы
  `searchStringAddition`, `viewStatusAddition`, `searchControlAddition`,
  рендерер синтезирует полосу состояния просмотра и строку поиска.
- Спрайт `icons.svg`: крестик плашки (`i-px-chip-x`) пересобран по эталону
  попиксельно — 124 прямоугольника вместо сборки из полупрозрачных
  прямоугольников.
- `TestForm::valueTableColumns` и `TestForm::tableSearchAdditions`.

### Изменено

- Дерево метаданных при открытии раскрыто только до корня; щелчок по объекту
  показывает модули и свёрнутые разделы состава со счётчиками («Реквизиты»,
  «Табличные части», «Формы»). Раньше одного щелчка хватало, чтобы развернуть
  объект целиком. Выбор формы из командной строки по-прежнему раскрывает
  ровно путь до неё.
- Пиксельный бюджет тринадцати форм переставлен на новую метрику: 12 337
  структурных пикселей по старой маске, 3 826 сразу после замены маски,
  сейчас — 1 580.

### Исправлено

- Кнопки формы снова рисуются: без команд формы конфигуратор кнопку не
  показывает, поэтому у форм тестовой базы появились `Commands` с `Action`,
  кнопки ссылаются на них через `CommandName`, в выгрузку пишется модуль формы
  с обработчиками. «Кнопки» — 154×133, «КоманднаяПанель» — 173×122.
- Полоса команд — платформенные 27 px в строке 30 px: снято по пикселю
  нижнего отступа полосы и оболочки элемента. Вертикальный стек кнопок идёт
  шагом 36 px, кнопка растягивается на ширину группы и центрирует подпись.
  Своя командная панель — та же полоса 27 px, кнопка на 60…86 с x=10.
- Таблица значений: своя командная панель не подменяется на `None`, если её
  путь к данным совпадает с главным реквизитом (подмена осталась только для
  динамического списка); корневая таблица не сдвигается оболочкой элемента.
- Полоса состояния просмотра (плашки «Поле1: Значение1») — 23 px плашек плюс
  8 px до сетки, сетка встаёт на 126. Крестик плашки — растровая площадка
  12×12 с кольцом 0,48 и диагоналями 0,32.
- Строка поиска в панели таблицы занимает 183…355 (поле 172 px), рамка поля —
  #b3ac86, подсказка — ~10,5 px цветом #c8c8c8 с отступом 2 px, поле на 1 px
  ниже кнопок.
- Шапка групп колонок: вертикальная группа с шапкой — одна физическая
  колонка, ячейка растягивается на все строки, подпись выравнивается по верху,
  шаг строки шапки — 31 px.
- Колонки таблицы значений приходят с типами (образец значения в обёртке
  `{"Pattern", ...}`, квалификаторы строками): «Количество» — 139 px,
  «Наименование» — 317 px и забирает остаток полотна.
- Авторская высота таблицы: остаток полотна забирает только таблица без
  высоты в форме или с `VerticalStretch=Да`; высота сетки считается как
  `round(шапка·31 + тело·30,67)`.
- Поля: рамка = авторская ширина в знаках · 10 + 11 px вставки + 21 px
  на каждую кнопку редактора; календарь и калькулятор нарисованы пиктограммами
  попиксельно (9×10 и 9×11); числовое поле показывает ноль с прижатием
  вправо; текстовые реквизиты с авторской шириной тянут дорожку вертикальной
  группы.
- Подписи: колонка считается по продвижениям GDI, округлённым по отдельности
  и сложенным (`captionLaneMetric`), зазор подписи — 4 px; заморозка коробки
  подписи — только там, где браузерный advance больше ячейки; вложенная
  горизонтальная группа держит свою колонку; диапазон «от:/до:/по:» просит
  ещё единицу.
- Переключатели: подписи списка выбора доезжают до модели (типизированное
  значение `S`/`N`/`B`), вид переключателя читается из блока `{8, …}`; булев
  `Tumbler` рисуется флажком 15×15 в общей колонке заголовков; строка выбора —
  17 px без полосы элемента, шаг Single 9 px.
- Картинки-декорации из библиотеки платформы рисуются 16 px
  (`StdPicture.Print` в таблице стандартных картинок, класс
  `fp-picture-library16`); `Border` у `PictureDecoration` убран из словаря —
  платформа отвергает его XDTO-исключением.
- Узкие полосы команд: фантомные 7 px больше не выталкивают кнопку «Ещё»
  за край колонки.
- Нижняя рамка страниц видна и над белым полем: у владельца страниц
  `padding-bottom: 0; margin-bottom: 1px`.
- Заголовок окна — 12.2 px с `padding: 1px 1px 2px` и цветом #99b4d1;
  заголовок группы — 15.5 px.
- Модель формы: сравнение кириллических имён типов через `QStringLiteral`
  вместо `QLatin1String` (поле даты рисовалось как текст), вид даты
  (`Date`/`DateTime`/`Time`) пишется рядом с типом; квалификаторы типа
  из бинарной формы (`stringLen`, `numberQ`); заголовок реквизита читается
  из четвёртого элемента записи, а не из первой колонки.
- Снимки для замера больше не делят рамку, `model.json` и поток сервера:
  у каждого снимка свои файлы, раздача многопоточная, копия ресурсов —
  только при реальном расхождении. Рендерер делает один повтор загрузки
  платформенной картинки; транзиентный отказ больше не меняет снимок.
- Гейт `control_fixtures` пишет вывод в UTF-8: на англоязычном Windows
  (cp1252) печать кириллицы в трубу падала с `UnicodeEncodeError`, и `ctest`
  на CI заканчивался ошибкой при прошедшей проверке. Консольный вывод
  не трогается — там кодировка потока не участвует.

## [0.7.0] — 2026-11-21

### Добавлено

- **Точный вид управляемых форм**: форма отображается браузерным рендерером
  конфигуратора 1С (проект BslEdit, MIT) внутри Microsoft Edge WebView2.
  Режим включается в меню «Вид → Точный вид форм (как в конфигураторе)» или
  переключателем «Вид: Упрощённый / Точный» в просмотре формы и запоминается
  в настройках (`MainWindow/exactFormView`). Доступен только в Windows и при
  установленном WebView2 Runtime; при его отсутствии приложение сообщает
  причину и остаётся на упрощённом рендерере.
- Модель формы для точного вида (`src/core/FormWebModel.*`): разобранный из
  контейнера `FormDocument` сериализуется в JSON в терминах XCF — элементы
  (`UsualGroup`, `Pages`/`Page`, `InputField`, `LabelField`, `CheckBoxField`,
  `Table` с колонками, `Button`, `Popup`, `LabelDecoration`), свойства
  (`Title`, `DataPath`, `Width`, `Group`, `Representation`, `Behavior`,
  `TitleLocation`, `HorizontalStretch`), командная панель со стандартными
  командами платформы, реквизиты и команды формы, метаданные владельца
  (`objectMeta`: вид объекта, имя, синоним, заголовки реквизитов). XML-файлы
  конфигурации не нужны: источник данных — тот же разбор скобочного формата.
- Элемент управления `WebView2Host` (`src/gui/web/`): виртуальный хост
  `https://qv8.local/`, все запросы которого обслуживает приложение (ресурсы
  рендерера — из qrc, модель формы — из памяти), поэтому сеть и временные
  файлы не используются. `WebView2Loader.dll` подгружается динамически,
  SDK-библиотека не линкуется. Отладочный журнал — переменная окружения
  `QTV8_WEBVIEW2_LOG=<файл>`.
- CLI: команда `form-model <файл> <объект> [--form <имя>] [-o файл]` —
  JSON-модель формы для рендерера; `--items` печатает дерево элементов формы
  с кодами типа, вида группы, ориентацией и разобранными свойствами.
- Командная строка GUI: ключ `--exact-form-view` (включить точный вид для
  открываемой формы, не меняя сохранённую настройку).
- Тесты: проверка структуры JSON-модели формы (теги, свойства, командная
  панель, `objectMeta`, реквизиты и команды).
- SDK WebView2 (заголовок, `WebView2Loader.dll`, лицензии) — в
  `3rdparty/webview2/`; описание архитектуры точного вида —
  [docs/form-exact-view.md](docs/form-exact-view.md).

## [0.6.1] — 2026-11-18

### Производительность

- `V8Container::find`/`indexOf` используют хеш-индекс по имени (без учёта
  регистра) вместо линейного поиска. На большой конфигурации (БП 3.0,
  15 523 объекта) загрузка метаданных ускорилась примерно в 2,5 раза.
- Вкладка «Контейнер» в GUI заполняется лениво, при первом открытии:
  на больших файлах это убирает ~1,5 с со старта приложения. Перед показом
  вкладки и контекстным меню дерево строится автоматически.
- `binary`-эвристика вынесена в `BinaryText`; для выгрузки сохранено
  распознавание UTF-16, для остальных мест — прежнее поведение.

### Изменено

- Рефакторинг без изменения поведения: `ConfigurationReader` разделён на
  `MetadataTextUtils`, `TypeResolver`, `SubscriptionParser` и `SectionBuilder`;
  общие эвристики текста и форматирования вынесены в `BinaryText`/`DisplayText`.
- CLI вынесен в библиотеку `qtv8reader_cli_lib` (`CliApplication` + `Output`),
  `main.cpp` оставлен тонким; добавлены golden-тесты команд.
- GUI разделён на `qtv8reader_gui` и `MainWindow*`-файлы по подсистемам;
  выделены `ThemeController`, `ModulePanel`, `PropertiesPanel`, `MetadataIcons`;
  добавлены offscreen-тесты панелей. Публичное поведение и формат файлов не менялись.
