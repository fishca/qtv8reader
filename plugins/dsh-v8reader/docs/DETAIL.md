# Плагин: 1С: чтение конфигураций

Страница правой панели DeepSeek Harness для чтения конфигураций и внешних
обработок 1С:Предприятие 8 (`.cf`, `.cfe`, `.epf`, `.erf`). Плагин не разбирает
формат сам: он вызывает `v8reader_cli` из этого же репозитория и показывает
готовый снимок.

## Что умеет

- **Вкладка «1С» в правой панели.** Кнопка `+` в правом сайдбаре открывает
  справочник, в нём — «1С: чтение конфигурации». Вкладка просит абсолютный путь
  к файлу, запоминает последний открытый путь в `localStorage` и переживает
  переключение вкладок (`keepMounted`).
- **Открытие из дерева Files.** `.cf`, `.cfe`, `.epf` и `.erf` из дерева файлов
  (и по ссылке на файл в чате) открываются той же панелью в правом сайдбаре:
  плагин объявляет рендерер документов для этих расширений, берёт абсолютный
  путь из метаданных вкладки и показывает дерево, состав объекта, модули и
  формы. «Обновить» в шапке документа начинает новую ревизию и перечитывает
  открытый экран; если файл заменён, панель показывает «файл изменился» и
  предлагает обновить. Документный рендерер регистрируется через
  `ctx.inject(['documentPreviews'])`, поэтому без пакета предпросмотра
  остаётся вкладка-страница.
- **Обзор файлов.** «Обзор…» открывает список каталога поверх панели: хлебные
  крошки от корня диска, переход к родительской папке, поле пути (другой диск,
  `\\server\share`, вставка пути к файлу), фильтр по имени, переключатель «Все
  файлы» (по умолчанию показаны только `.cf`, `.cfe`, `.epf`, `.erf`; переключатель
  «Все файлы» показывает и остальные, но выбрать их нельзя). Клик по папке входит в неё, клик по
  файлу сразу открывает его. Обзор стартует с последнего каталога из
  `localStorage`; если тот недоступен, молча переходит в домашний — с кнопками
  «Повторить» и «Домашняя папка» в баннере ошибки. Кнопка «Открыть» с пустым
  полем открывает обзор, а не молчит.
- **Дерево метаданных как в 1С.** Корень «Конфигурация», под ним категории
  (справочники, документы, обработки, языки, …), под категориями объекты, под
  выбранным объектом — его разделы: реквизиты, табличные части, формы, команды,
  макеты и модули. Листья форм, макетов и модулей сразу открывают форму,
  табличный документ или код; листья остальных разделов переключают вкладку
  состава объекта. Вложенные реквизиты
  показываются с отступом. Дерево фильтруется по имени и синониму, длинные
  категории и разделы выдаются порциями. Состав объекта запрашивается одним
  `state`-запросом при выборе объекта и кэшируется на хосте.
- **Состав объекта.** Реквизиты, табличные части, формы, макеты, команды и
  прочие разделы — таблицей «имя, синоним, тип»; в разделе «Формы» у каждой
  строки есть кнопка, открывающая точный вид формы.
- **Модули с подсветкой BSL.** Правила портированы из `src/gui/BslHighlighter`:
  ключевые слова ru/en без учёта регистра, директивы `#…` в начале строки,
  аннотации `&…`, числа, строки с удвоенными кавычками и комментарии `//`.
  Палитра светлая и тёмная, как в `BslHighlightSettings`, и следует теме
  приложения через сервис `theme`. Есть номера строк, перенос по ширине,
  размер шрифта, отключение подсветки и копирование; настройки хранятся в
  `localStorage['dsh.v8reader.code.v1']`. Модуль открывается целиком: строки
  токенизируются и показываются порциями по 1500 с кнопкой «Показать ещё», так
  что большой модуль не тормозит панель и остаётся доступен до конца.
- **Формы точного вида.** Кнопка у формы (в дереве или в составе объекта)
  открывает её в панели: приложение отдаёт `form-model --json`, плагин
  вставляет модель в свою страницу рендерера `resources/formpreview` и
  показывает её в `<iframe>`. Масштаб 50–150 % (`localStorage['dsh.v8reader.form.v1']`),
  кнопка «Обновить», возврат к объекту. Ошибка CLI или рендерера показывается
  баннером панели, а не JSON внутри рамки.
- **Макеты MXL.** Кнопка у макета (в дереве или в разделе «Макеты») открывает
  табличный документ: приложение отдаёт `mxl --template <имя> --html -`, а
  панель показывает готовую самодостаточную страницу в `<iframe>` без
  скриптов. Масштаб 25–400 % и «по ширине»
  (`localStorage['dsh.v8reader.mxl.v1']`), «Обновить», возврат к объекту.
  Масштаб применяется к уже загруженному документу, поэтому смена масштаба не
  перезапрашивает страницу; «по ширине» следит за шириной панели.

## Требования

Нужен `v8reader_cli` версии **0.14.0 или новее** (`view --json` схема 1 —
и `view`, и `form-model`). Плагин ищет его в таком порядке:

1. `cliPath` в строке плагина (`config: { cliPath: "…" }`);
2. переменная окружения `V8READER_CLI`;
3. `out/cli-deploy/v8reader_cli.exe`, затем `out/mingw`, `out/vs`, `out/build`
   относительно этого репозитория — удобство для разработки;
4. `PATH`.

Готовый бинарник должен быть развёрнут вместе с библиотеками Qt: собранный в
дереве `out/mingw` он без `windeployqt` не запускается. Ответ `/v8reader/health`
перечисляет проверенные пути и найденную версию — по нему видно, что именно не
так.

Веб-рендерер формы лежит в пакете плагина (`assets/formpreview`, копия
`resources/formpreview`). Копию обновляет `npm run assets`; она закоммичена,
поэтому установка из репозитория ничего не собирает. Если каталога нет,
`/v8reader/form` отвечает кодом `assets-missing` с подсказкой запустить
`npm run assets`.

## Ограничения

- Только чтение: плагин ничего не записывает и не меняет.
- Один запрос на экран: дерево, состав объекта, модуль и форма запрашиваются
  отдельно; на большой конфигурации первый вызов занимает около секунды, ответ
  кэшируется на хосте.
- Открываются только файлы с расширением `.cf`, `.cfe`, `.epf`, `.erf`;
  остальные получают `unsupported-format`.
- Обзор каталога читается синхронно (`readdir` + `stat` для размеров, не больше
  1000 записей и 300 замеров размера на ответ), поэтому на сетевой папке с
  тысячами файлов первый ответ может занять секунды; панель показывает
  «Чтение папки…» и на это время гасит список.
- Формы 8.2 с короткой записью макета показываются с известными упрощениями
  (см. `docs/research/forms-format.md`). Модель формы кэшируется по
  `(путь, размер, mtime, объект, форма)`.
- Вкладка документа из дерева Files и страница «1С» рисуются в правом
  сайдбаре веб-GUI; Electron-десктоп без HTTP-маршрута не поддерживается.

## Маршруты

| Маршрут | Ответ |
|---|---|
| `GET /v8reader/state?path=[&object=&module=]` | документ `view --json` (схема 1) |
| `GET /v8reader/browse?path=[&all=1]` | один уровень каталога для обзора: `dir`, `parent`, `breadcrumbs`, `entries[{name,path,kind,size?}]`, `truncated`, `hiddenCount` |
| `GET /v8reader/form?path=&object=&form=` | готовая HTML-страница формы: модель `form-model` уже внутри, ассеты подключаются через `<base href="/v8reader/assets/">` |
| `GET /v8reader/mxl?path=&object=&template=` | готовая HTML-страница табличного документа: самодостаточная таблица из `mxl --html -`, без скриптов; кэшируется по `(путь, размер, mtime, объект, макет)` |
| `GET /v8reader/assets/<путь>` | файл веб-рендерера (`model.html`, js, css, svg, стандартные картинки); `Cache-Control: no-cache`, ETag для ревалидации |
| `GET /v8reader/health` | `{ ok, schema, minCliVersion, cli: { found, path, version, searched } }` |

Ошибки приходят как `{ error: { code, message, detail? } }` со стабильными
кодами `bad-path`, `unsupported-format`, `cli-failed`, `cli-missing`, `cli-old`,
`too-large`, `timeout`, `denied`, `forbidden`, `not-found`, `method-not-allowed`,
`bad-request` (не хватает `object`/`form`) и `assets-missing` (нет копии
рендерера).

## Установка

```
plugin_manager { action: install_bundle, target: "<путь к plugins/dsh-v8reader>" }
```

Для разработки клиент собирается из `src/client` командой `npm run build`
(esbuild); `client.js` закоммичен, поэтому установка его не пересобирает.
`npm run assets` обновляет копию рендерера формы из `resources/formpreview`.
