# Обзор: 1C Configuration tree / MetadataViewer1C

Ссылки:

- Marketplace: [1C Configuration tree](https://marketplace.visualstudio.com/items?itemName=whiterabbit.1c-configuration-tree)
  (publisher whiterabbit, 785 установок, бесплатно);
- Исходники: [asweetand-a11y/MetadataViewer1C](https://github.com/asweetand-a11y/MetadataViewer1C)
  (TypeScript, MIT, ~75 звёзд).

Это один и тот же продукт: описание в Marketplace и README репозитория совпадают
(те же команды `metadataViewer.*`, тот же функционал). Расширение VS Code / Cursor
для работы с метаданными конфигураций **в форматах XML/EDT** (пары
`ConfigDumpInfo.xml` + `Configuration.xml`), а не с бинарными `.cf/.epf`.
Таким образом, по отношению к qtv8reader это не конкурент, а комплементарный
продукт: мы читаем бинарные контейнеры, они — выгрузки Designer XML/EDT.

## Что умеет

- Дерево метаданных по XML/EDT: все стандартные ветки, модули BSL, шаблоны,
  предопределённые данные, формы, СКД, роли.
- **Просмотр и редактирование макетов** (Template.xml): таблица с форматами,
  цветами, границами, узорами, шрифтами, объединениями, именованными областями,
  примечаниями ячеек, параметрами `[[Имя]]`.
- **Предпросмотр форм** (FormPreviewApp), предпросмотр/редактор СКД,
  редактор прав роли (RLS), редактор предопределённых элементов,
  редактор метаданных объекта, поиск по дереву, фильтр по подсистеме.
- Трёхуровневый кэш (L1 конфигурация, L2 объект, L3 элементы) и переиндексация.
- Автогенерация BSL, закладки, управление отступами, MCP-сервер и т. п.

## Что полезно для qtv8reader

### Взято сразу (реализовано в ветке feature/mxl_reader)

1. **Семантика типов линий рамки MXL** (`src/utils/spreadsheetCellLineType.ts`):
   коды 0 — нет, 1 — сплошная, 2 — точечная, 3 — двойная, 4 — тонкий пунктир,
   5 — жирный пунктир, 6 — большой пунктир (совпадает с EDT
   `SpreadsheetDocumentCellLineType`). Исправлен рендер `MxlView`
   (раньше 4/5/6 маппились неточно).
2. **Формула автовысоты строки** (`calculateRowHeight`):
   `max(20, ceil(размер_шрифта_px * 1.2 + 8))`, где px = pt * 96/72.
   Принята в `MxlView::cellPixelHeight`.
3. Подтверждены константы и подходы: ширина колонки по умолчанию 72 единицы,
   шрифт в пикселях = pt * 96/72, высота строки не каскадируется.

### Кандидаты на следующие шаги

1. **Именованные области и параметры макета** (`templateUtils.ts`,
   `NamedAreaDialog`, `TemplateTable.js`): в MXL8 в хвосте есть таблица
   именованных областей; можно парсить в `MxlDocument`, показывать списком в
   «Составе» и подсвечивать область в `MxlView`. Полезно для печатных форм.
2. **Состав подсистемы и фильтр по подсистеме** (`subsystemMembership.ts`):
   у нас уже читается иерархия подсистем; в элементе подсистемы есть таблица
   состава `{класс_объекта, GUID}` — можно показывать «Объекты подсистемы» и
   фильтровать дерево (как в 1С: «Действия → По подсистемам»).
3. **Примечания/расшифровки ячеек**: в макетах хранятся notes/details;
   их можно показывать в свойствах ячейки/всплывающей подсказке.
4. **Кэширование и инкрементальное обновление**: L1/L2/L3-подход полезен,
   если появятся очень большие конфигурации и повторные открытия; для
   read-only ридера достаточно ленивого разбора, но идея переиндексации узла
   применима к нашему дереву.
5. **Предпросмотр форм** (`FormPreviewApp`): большая отдельная задача
   (в бинарном `.cf` формы — сериализованная модель 1С). Их реализация —
   хороший референс UI, но портировать её целиком не стоит.
6. **Редактор прав роли / предопределённые данные**: аналог в 1С; для нас
   возможно в режиме просмотра (права в `.cf` хранятся как XML/текст внутри
   элементов роли — надо проверить на реальном файле).
7. **Поддержка XML/EDT-выгрузок**: если понадобится читать конфигурации,
   выгруженные в Designer XML, можно взять их модели/схемы как референс
   (но код TypeScript и завязан на webview; проще свой XML-ридер).

### Что не подходит

- Редактирование метаданных, XML-патчинг, генерация BSL, MCP — вне задачи
  read-only ридера.
- Веб-рендеринг (React/webview) не переносится в Qt-приложение; полезны только
  формулы разметки и семантика полей.
- Проект не читает бинарные `.cf/.epf/.cfe` — наш сценарий остаётся уникальным.
