# Чтение и отображение MXL (табличный документ 1С) в qtv8reader

Исследование: какие есть сторонние средства чтения формата `.mxl`, что можно
переиспользовать в C++/Qt и как встроить просмотр табличных документов в
приложение.

## 1. Какие бывают MXL

| Поколение | Файл | Внутренний формат | Статус |
|---|---|---|---|
| 1С 7.7 | `.mxl` | бинарный `MOXCEL`, сериализация MFC `CSheetDoc`, версии 6/7 | устаревший, в 8.x не используется |
| 1С 8.х (8.2/8.3/BAS) | `.mxl`, макеты в `.cf/.cfe/.epf`. | «MXL8»: 16-байтный заголовок + текстовое тело в нотации 1С | актуальный |

Признаки: у 7.7 после `MOXCEL` идут пять нулевых байт и байт версии 6/7; у 8.x —
`MOXCEL\0`, затем WORD-версии (8, 1, sub = 9/12/…), BOM UTF-8 и тело `{8,1,12,...}`.

## 2. Устройство MXL8 (проверено на реальном макете БП 3.0)

Разобрали макет `ПФ_MXL_АвансовыйОтчет` из `1Cv8_bp.cf`
(извлечён нашим `v8reader_cli extract`, 24 395 байт):

- заголовок `MOXCEL\0`, версия 8.1.12, BOM, далее тело `{8,1,12, …}` — 21 652
  символа, корневой объект из 1290 полей;
- блок строк начинается с 16-го поля корня (индекс 15): число строк 74,
  строки разрежены, в них 427 ячеек, максимум 24 колонки, 190 текстовых ячеек;
- в хвосте: 54 объединения ячеек, таблица форматов, 5 шрифтов, 4 цвета.

Ключевые части тела (по [описанию формата](https://github.com/azubar/SpreadSheet/blob/main/docs/format-mxl.md)):

1. **Строки/ячейки**: `{число_строк, (номер_строки, формат_строки, число_ячеек,
   (номер_колонки, {маркер, индекс_формата, …})…)…}`. Маркер ячейки — битовая
   маска: 2 — типизированное значение `{"S","текст"}`, 4 — ссылка-расшифровка,
   16 — локализованный текст `{n, есть_текст, {язык, текст}}`.
2. **Форматы**: `{флаги, значения по установленным битам}` — шрифт, рамки Л/В/П/Н,
   цвет рамок, высота строки (1/288"), ширина колонки (1/8 ширины символа),
   выравнивания, цвета текста/фона, тип узора (0–17, 255 — нет), контроль текста
   (авто/обрезать/забивать/переносить), поворот текста.
3. **Хвост**: группа колонок по умолчанию, доп. группы ширин, карта
   «строка → группа», графические объекты, объединения, таблица форматов,
   таблица шрифтов, цвета (`COLORREF` в BGR), картинки (`#base64:`).
4. **Графика**: прямоугольники, надписи, картинки, OLE/диаграммы (частично).

Важно: тело — та же скобочная нотация, что и метаданные конфигурации, поэтому
наш существующий `V8Text` (`src/core/V8Text.*`) уже умеет её лексически разбирать;
нужен только семантический слой (модель документа) и рендер.

Где MXL лежит в файлах 1С:

- отдельные `.mxl` — обычные файлы;
- в `.cf/.epf/.cfe` макет — элемент контейнера, содержимое которого уже полный
  MXL-файл (мы это видим: извлечённый `.bin` начинается с `MOXCEL`), т.е.
  читать нужно так же, как отдельный файл;
- в выгрузке Designer XML (EDT) — `Template.xml` с той же информацией в XML
  (проще парсить, но наш ридер работает с бинарными контейнерами).

## 3. Готовые сторонние средства

| Проект | Язык / лицензия | Что умеет | Пригодность |
|---|---|---|---|
| [azubar/SpreadSheet](https://github.com/azubar/SpreadSheet) | Rust, MIT (заявлена в README; файла LICENSE в корне нет) | полный разбор MXL8: строки, форматы, шрифты, цвета, рамки, объединения, ширины, узоры, картинки, рисунки; рендер в JPEG/PNG (tiny-skia, встроенный шрифт) | лучший референс для C++-порта; как библиотека — только через Rust/C ABI и рендер в картинку |
| [alexiosus/mxl-merge-tool](https://github.com/alexiosus/mxl-merge-tool) | Python, MIT | структурный разбор строк/ячеек, diff и 3-way merge, HTML-предпросмотр **силами 1С** | MIT-код-референс парсера; рендер делегирует платформе |
| [SergiosZZz/mxl-column-editor](https://github.com/SergiosZZz/mxl-column-editor) | Python, MIT | разбор строк/колонок, редактирование MXL, предпросмотр через 1С | референс структуры; не рендерер |
| [VampiRUS/mxl-reader](https://github.com/VampiRUS/mxl-reader) | PHP, MIT | только MXL 7.7 (v6), текстовые данные | не подходит для 8.x |
| [yoksel.net.ru «Формат MOXCEL»](http://yoksel.net.ru/FormatMOXCEL/Vvedenie/print) | документация | подробное описание бинарного MXL 7.7 | только 7.7 |
| [sergeyfedyakov/v8unpack-mcp](https://github.com/sergeyfedyakov/v8unpack-mcp) | Python, MIT | `read_template`: MOXCEL → дерево + список строк (без раскладки) | быстрый способ получить текст; не рендер |
| [comol/ai_rules_1c](https://github.com/comol/ai_rules_1c) и «mxl-expert» | JSON DSL | создание/разбор `Template.xml` в XML-выгрузке | не бинарный MXL |
| [DmitryDreytser/v7Moxel](https://github.com/DmitryDreytser/v7Moxel) | C# | 7.7: MXL → Excel/HTML/PDF | не 8.x |
| Йоксель (yoksel) | freeware (не OSS) | просмотр/конвертация MXL и XLS, рендер в картинки | только как эталон поведения |
| 1С:Предприятие | проприетарная | `SpreadsheetDocument.Read` + `Write(HTML/XLSX/PDF)` — точный рендер | требуется установленная лицензионная 1С |

Готовой C++-библиотеки для MXL8 не нашлось (поиск по GitHub: C++/Qt-проектов
нет; MXL в названиях — это медиа-формат Media eXchange Layer).

## 4. Варианты для C++/Qt

### A. Свой парсер + рендер на Qt (рекомендуется)

- Парсер: `MxlDocument` (строки, ячейки, форматы, шрифты, цвета, линии,
  объединения, группы колонок, рисунки, картинки); лексер — существующий
  `V8Text`, семантика — по описанию формата и MIT-референсам.
- Рендер: `QPainter` в `QAbstractScrollArea` (или `QGraphicsScene`) с
  масштабом, прокруткой, выделением текста; печать/PDF — через `QPrinter`.
- Плюсы: без внешних зависимостей и без 1С, кроссплатформенно, полный
  контроль, лицензионно чисто; текст можно копировать, позже — поиск по ячейкам.
- Минусы: нужно реализовать layout (перенос, поворот, объединения) и
  обработать экзотику (узоры, OLE, диаграммы).
- Оценка MVP (текст + строки/колонки/форматы/шрифты/цвета/рамки/объединения):
  парсер ~2–3 дня, рендер и виджет ~3–5 дней, тесты/демо ~2 дня.

Быстрый вариант: `MxlDocument::toHtml()` + `QTextBrowser` — за 1–2 дня, но без
точных ширин/поворотов/узоров; годится как первый предпросмотр и экспорт в HTML.

### B. Переиспользовать Rust-крейт `spreadsheet` (azubar/SpreadSheet)

- Собрать `spreadsheet` как `staticlib`/`cdylib` с C-обёрткой `mxl_parse`/`mxl_render`
  и вызывать из Qt; рендер вернёт PNG, показываемый в `QLabel`/`QImage`.
- Плюсы: готовый полный парсер и рендер (узоры, картинки, поворот, рамки).
- Минусы: Rust-тулчейн в сборке (Windows/Linux CI), ABI и версии, только
  картинка (нельзя выделить/скопировать текст), лицензия требует уточнения
  (README заявляет MIT, но файла LICENSE нет — нужно письменное подтверждение).

### C. Внешний Python-инструмент (mxl-merge-tool / column-editor)

- Вызывать Python-скрипт, получать JSON/HTML, показывать в Qt.
- Плюсы: быстро, MIT-код уже умеет разбирать строки/ячейки.
- Минусы: Python в комплекте поставки, скорость, сложность упаковки; рендер
  всё равно через 1С, т.е. не решает задачу «показать в своём приложении».

### D. Рендеринг силами 1С (как в MIT-инструментах)

- Внешняя обработка/тонкий клиент: `SpreadsheetDocument.Read` →
  `Write(..., HTML)` (или XLSX/PDF), показывать HTML в `QTextBrowser`/`QWebEngine`.
- Плюсы: 100 % точное отображение.
- Минусы: нужна установленная лицензионная 1С; не тянет на «самодостаточное
  приложение». Годится как **опциональный** режим «открыть в 1С» / «экспорт
  через 1С», если платформа найдена.

### E. Работать с XML-выгрузкой (`Template.xml`)

- Если конфигурация выгружена в Designer XML/EDT, макеты — это XML, который
  легко разобрать `QXmlStreamReader` без своих бинарных парсеров.
- Минусы: наш ридер читает бинарные `.cf/.epf`; XML-выгрузки — отдельный
  сценарий (можно поддержать позже как дополнительный источник).

## 5. Рекомендация

1. Реализовать **свой парсер MXL8 на C++** в `src/core/`:
   - `MxlDocument`: строки/ячейки/форматы/шрифты/цвета/линии/объединения/
     группы колонок/рисунки/картинки;
   - чтение из элемента контейнера и из файла `.mxl`;
   - лексер — `V8Text`, семантика — по `docs/format-mxl.md` и MIT-референсам
     (mxl-merge-tool, mxl-column-editor, Rust-парсер как логика, с атрибуцией).
2. Первый этап рендера — `QPainter`-виджет с прокруткой и масштабом:
   сетка, объединения, шрифты, цвета, рамки, выравнивание, перенос текста.
3. Второй этап — узоры заливки, поворот текста, картинки (`#base64:`),
   прямоугольники/надписи, печать/PDF через `QPrinter`.
4. Встроить в GUI: у макета (`Template`) — предпросмотр «Табличный документ»
   в отдельной вкладке; в CLI — команду `mxl` с выводом текста/HTML/PNG.
5. Тесты: демо-файлы из
   [mxl-demo-collection](https://github.com/azubar/SpreadSheet/tree/main/mxl-demo-collection)
   (цвета, узоры, границы, объединения, печать), реальные макеты БП; эталон —
   HTML, сохранённый из 1С (если платформа доступна) или скриншоты Йокселя.
6. Опционально — режим «Открыть через 1С» (D) для 100 % точного вида и экспорта,
   если платформа установлена.

## 6. Риски и ограничения

- Формат официально не документирован; часть полей хвоста не расшифрована —
  парсер должен быть «терпимым» (пропускать неизвестное, не падать).
- Различия версий 8.1.9/8.1.12/8.3.x: блок строк ищется по форме, а не только
  по индексу 15.
- 7.7-формат (v6/v7) — отдельный бинарный формат, в MVP не входит.
- Экзотика (OLE, диаграммы, сложные узоры) может отображаться упрощённо.
- Лицензии: MIT-проекты можно использовать с атрибуцией; у Rust-парсера
  лицензия заявлена, но файла LICENSE нет — перед копированием кода уточнить.
