# qtv8reader 0.3.0

Первый релиз с полноценным деревом метаданных в стиле конфигуратора 1С.

## Что нового

### Дерево метаданных

- **Стандартные ветки конфигурации** в порядке 1С: Общие, Константы, Справочники,
  Документы, Журналы документов, Перечисления, Отчёты, Обработки, Планы видов
  характеристик, Планы счетов, Планы видов расчета, Регистры сведений,
  Регистры накопления, Регистры бухгалтерии, Регистры расчета, Бизнес-процессы,
  Задачи, Внешние источники данных.
- **Вид по умолчанию как в конфигураторе**: при открытии файла раскрыт только
  корень, все ветки свёрнуты; в правой панели — свойства конфигурации.
- **Пустые стандартные ветки показываются** (как в 1С), у объектов —
  ленивая загрузка состава при раскрытии узла.
- **Иерархия подсистем**: вложенные подсистемы читаются из состава родительской
  подсистемы и отображаются вложенным деревом; при выборе подсистемы видно
  количество вложенных и их список на вкладке «Состав».
- **Порядок ветки «Общие»** соответствует руководству разработчика 1С 8.3:
  Подсистемы, Общие модули, Параметры сеанса, Роли, Общие реквизиты,
  Планы обмена, Критерии отбора, Подписки на события, Регламентные задания,
  Боты, Функциональные опции, Параметры функциональных опций, Определяемые типы,
  Хранилища настроек, Общие команды, Группы команд, Общие формы, Общие макеты,
  Общие картинки, XDTO-пакеты, Web-сервисы, HTTP-сервисы, WS-ссылки,
  WebSocket-клиенты, Сервисы интеграции, Элементы стиля, Стили, Языки.
- **Планы обмена** находятся внутри «Общие»; **Нумераторы** и
  **Последовательности** — первыми в ветке «Документы», перед документами.
- **Иконки в стиле 1С** для типов объектов и разделов: открытый набор
  metadata-icons (MIT), перекрашенный в палитру 1С и отрендеренный в PNG
  (16/24/32 px). Отдельных зависимостей от QtSvg нет.
- **Поиск по дереву** (Ctrl+F) по имени, синониму и GUID с авто-раскрытием
  найденных веток.

### Объекты и состав

- Реквизиты, табличные части (с реквизитами), формы, команды, макеты,
  измерения, ресурсы, значения перечислений, признаки учёта и графы журналов.
- Модули: объекта, менеджера и форм; тексты модулей и текст метаданных объекта.
- Дерево элементов контейнера, предпросмотр и сохранение элементов.

### Прочее

- CLI: `info`, `list`, `tree`, `dump`, `metadata`, `modules`, `composition`,
  `extract`, `extract-all`.
- Выгрузка объекта или всей конфигурации на диск (`metadata.txt`,
  `composition.txt`, `info.txt`, модули `.bsl`, формы, макеты, двоичные данные).
- Режимы `--smoke` и `--screenshot` для проверки без показа окна;
  `--expand-common` и `--expand-documents` для раскрытия соответствующих веток.

## Поддерживаемые форматы

- `.cf` — конфигурация;
- `.cfe` — расширение конфигурации (через `configinfo`);
- `.epf` / `.erf` — внешняя обработка / внешний отчёт;
- `.cfu` — файл, сжатый целиком;
- контейнеры 1С:V8 форматов 1.5 и 1.6, включая сжатые блоки и цепочки блоков.

## Готовые сборки

### Windows 10/11 x64

`qtv8reader-0.3.0-windows-x86_64.zip` — портативная сборка: Qt и все библиотеки
внутри, установка не нужна. Распаковать архив и запустить `qtv8reader.exe`
(рядом лежит `v8reader_cli.exe`).

### Linux x64

- `qtv8reader-0.3.0-linux-x86_64.AppImage` — один самодостаточный файл:

  ```sh
  chmod +x qtv8reader-0.3.0-linux-x86_64.AppImage
  ./qtv8reader-0.3.0-linux-x86_64.AppImage
  ```

  Требуется glibc 2.35+ (Ubuntu 22.04+, Debian 12+, Fedora 36+).

- `qtv8reader-0.3.0-linux-x86_64.tar.gz` — те же бинарники с библиотеками,
  включая консольную утилиту `bin/v8reader_cli`.

Контрольные суммы — в файле `SHA256SUMS`.

## Проверено

- 45 автотестов (контейнеры 1.5/1.6, текст 1С, модель конфигурации, состав,
  модули, выгрузка, расширения, внешние обработки, ленивый разбор).
- Реальные файлы: «Бухгалтерия предприятия 3.0» `.cf` (15 523 объекта,
  42 категории), внешняя обработка `.epf`, расширение `.cfe`.
- CI: сборка и тесты на Windows (MSYS2/UCRT64) и Linux (Ubuntu 22.04).

## Ограничения

- Только чтение.
- Не поддерживаются 1CD-базы (хранилище конфигурации); читаются файловые
  контейнеры `.cf/.cfe/.epf/.erf/.cfu`.
- Тексты модулей без явных признаков кода могут не распознаваться.
