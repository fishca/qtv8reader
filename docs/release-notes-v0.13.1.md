# qtv8reader v0.13.1

**26 ноября 2026**

Патч-релиз к 0.13.0. В 0.13.0 сборка на CI падала из-за того, что гейт
тестовой базы печатал кириллицу в трубу, а на англоязычном Windows у неё
кодировка cp1252 — `UnicodeEncodeError` после успешно прошедшей проверки.
Тогда хелпер был встроен только в гейт. 0.13.1 закрывает класс целиком:
общий модуль и все десять инструментов тестовой базы.

Просмотрщик, рендерер и разбор форм не менялись — для пользователя разницы
с 0.13.0 нет.

## Главное

- **Общий модуль `tools/console_utf8.py`.** `use_utf8_stdio()` первой строкой
  `main()` переводит `stdout` и `stderr` в UTF-8 (для консоли это no-op:
  на Windows Python и так пишет туда UTF-8 через консольный API).
  Подключён во всех инструментах: `control_base.py`, `control_compare.py`,
  `control_fixture_check.py`, `control_matrix.py`, `control_refs.py`,
  `control_vocab.py`, `form_view_measure.py`, `form_view_probe.py`,
  `form_view_flaky_serve.py`, `form_xml_compare.py`.
- **`isatty()` не годится как признак консоли.** На Windows поток, отданный
  в `DEVNULL`, отвечает «это терминал», и первая версия правки (проверка
  «не консоль — тогда UTF-8») оставляла cp1252. Это вылезло на сервере
  раздачи `form_view_measure.py serve`, который `control_compare.py`
  запускает с заглушённым выводом: сервер падал на первой же печати, и
  сверка сообщала «не удалось поднять локальный сервер». Теперь поток
  переводится в UTF-8 всегда; для консоли на Windows это и так UTF-8 через
  консольный API, там поведение не меняется.

## Почему это было нужно

Гейт `control_fixtures` появился вместе с тестовой базой и в CI проверяется
`ctest`-ом. На `windows-latest` вывод Python идёт в трубу с кодировкой
платформы (cp1252), и итоговая печать «форм проверено: 13, расхождений
модели с Form.xml нет» падала с `UnicodeEncodeError` — проверка к этому
моменту уже прошла, но тест возвращал ошибку, а с ним и весь шаг `Test`.
Linux-раннер работает в UTF-8 и был зелёным.

В 0.13.0 хелпер был просто скопирован в гейт. Достаточно было запустить
под cp1252 любой другой инструмент — `control_compare.py --all`,
`control_matrix.py`, `control_refs.py`, — чтобы получить ту же ошибку.
Теперь реализация одна, и она проверена для всех десяти.

## Проверено

- `ctest` 5/5 — обычный прогон и прогон с `PYTHONIOENCODING=cp1252`;
  в набор добавлен тест `tools_utf8`, который печатает справку гейта под
  cp1252 (без хелпера это падало бы с `UnicodeEncodeError`).
- `--help` каждого из десяти инструментов под `PYTHONIOENCODING=cp1252`:
  код 0, вывод — валидный UTF-8 с кириллицей.
- `control_compare.py --all --check` под cp1252: тринадцать форм,
  структурные расхождения **1 580**, все формы в бюджете `baseline.json`.
- `control_compare.py --form ПоляВвода` под cp1252: сервер раздачи
  поднимается, снимок снимается, итоговая строка печатается, код 0
  (структура 15 px, как в бюджете).
- CI: Build (main) и Release (v0.13.1) — зелёные.

## Готовые сборки

### Windows 10/11 x64

`qtv8reader-v0.13.1-windows-x86_64.zip` — портативная сборка, Qt и все
библиотеки внутри, установка не требуется. Распаковать и запустить
`qtv8reader.exe`. Для точного вида нужен WebView2 Runtime; без него программа
работает как обычно и показывает форму в упрощённом виде.

### Linux x64

- `qtv8reader-v0.13.1-linux-x86_64.AppImage` — самодостаточный файл
  (glibc 2.35+):

  ```sh
  chmod +x qtv8reader-v0.13.1-linux-x86_64.AppImage
  ./qtv8reader-v0.13.1-linux-x86_64.AppImage
  ```

- `qtv8reader-v0.13.1-linux-x86_64.tar.gz` — бинарники с библиотеками,
  включая `bin/v8reader_cli`.

Контрольные суммы — в `SHA256SUMS`.
