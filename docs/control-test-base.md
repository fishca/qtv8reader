# Тестовая база контролов управляемых форм

База нужна, чтобы сверять вид каждого контрола управляемой формы с
конфигуратором не на одной форме «Авансового отчёта», а на наборе форм,
которые мы сами создаём и меняем. Исходники базы лежат в репозитории, сама
база — одноразовый артефакт на машине разработчика.

## Что где лежит

| Что | Где |
|---|---|
| Скелет пустой конфигурации, снятый платформой | `tests/fixtures/controlbase/skeleton` |
| Спецификация форм и контролов | `tests/fixtures/controlbase/spec/controls.json` |
| Выгрузка конфигурации в файлы (фикстура) | `tests/fixtures/controlbase/ConfigFiles` |
| Контейнер для просмотрщика | `tests/fixtures/controlbase/1Cv8_controls.cf` |
| Эталоны из конфигуратора | `tests/fixtures/controlbase/refs` |
| Базовый уровень текстовых расхождений | `tests/fixtures/controlbase/baseline.json` |
| Словарь тегов и свойств по корпусу БП | `tests/fixtures/controlbase/vocab.json` |
| Файловая информационная база | `E:\work\1cv83.db\qtv8db` (по умолчанию) |

Конфигурация называется «Контролы управляемых форм», в ней одна обработка
`Контролы`, а в ней — по форме на семейство контролов. Формы описаны
реквизитами самой формы: так поля и таблицы получают настоящие типы без
объектов-носителей.

## Конвейер

```
spec/controls.json ──► control_base.py build ──► база qtv8db ──► 1Cv8_controls.cf
                                   │                 │
                                   └── платформа нормализует выгрузку (pull)
                                                     │
                       конфигуратор: control_refs.py capture ──► refs/<форма>.png
                                                     │
   v8reader_cli form-model + headless Chrome: control_compare.py ──► out/control/**
```

### 1. Собрать базу и контейнер

```powershell
python tools/control_base.py build
```

Команда генерирует выгрузку из спецификации, создаёт базу (если её нет),
загружает конфигурацию (`/LoadConfigFromFiles` + `/UpdateDBCfg`), **забирает
нормализованную выгрузку обратно** (`/DumpConfigToFiles`) и сохраняет
контейнер (`/DumpCfg`). Обратный дамп важен: платформа сама дописывает
служебные элементы (контекстное меню, расширенную подсказку), переставляет
свойства в порядке схемы и считает хеши — фикстурой становится именно он.

Платформа берётся из спецификации (`"platform": "8.3.27.2342"`): эталоны
снимаются той же версией, иначе вид контролов не совпадёт.

### 2. Снять эталоны из конфигуратора

```powershell
python tools/control_refs.py capture --all
python tools/control_refs.py capture --form ПоляВвода
python tools/control_refs.py list
```

Скрипт запускает конфигуратор, для каждой формы находит её фильтром дерева,
открывает, ждёт синюю рамку полотна предпросмотра (цвет `#1E90FF`, 2 px),
обрезает ровно по внутреннему краю и сохраняет PNG с манифестом (размер,
хеш, дата). Захват идёт в интерактивном сеансе на экране 1920×1080 с
развёрнутым окном конфигуратора; если раскладка другая, поправьте координаты
в `refs/ui.json` (скрипт перезаписывает его при каждом запуске) или ключом
`--calibration`.

### 3. Сверить наш рендер с эталоном

```powershell
python tools/control_compare.py --all
```

Для каждой формы собирается модель (`v8reader_cli form-model`), снимается
страница рендерера в размере эталона и считается расхождение. Пиксели делятся
на **структурные** (рамки, линии, заливки, значки) и **текстовые** (края
глифов: GDI платформы и DirectWrite в Chromium расходятся принципиально).
Результат — `out/control/<форма>/{ref,ours,diff,pair}.png`, сводка —
`out/control/control-report.md`. Ключ `--update-baseline` фиксирует текущий
уровень текстовых расхождений в `baseline.json`.

Приёмка по контролу: **структура 0**, текст не выше базового уровня.

### 4. Гейт модели (без 1С и без Chrome)

```powershell
python tools/control_fixture_check.py --cli out/mingw/v8reader_cli.exe
```

Сравнивает JSON-модель каждой формы фикстуры с её `Ext/Form.xml`: теги, имена,
порядок и значения свойств. Это же проверяется в `ctest` (`control_fixtures`),
поэтому потери свойств при разборе контейнера ловятся в обычном CI.

## Как добавить контрол

1. Дописать форму или элемент в `spec/controls.json` (теги и свойства — как в
   `Form.xml`, значения: строка/число/`{"title": "..."}`).
2. `python tools/control_base.py build` — платформа проверит выгрузку; ошибки
   печатаются из журнала `/Out`.
3. `python tools/control_refs.py capture --form <форма>`.
4. `python tools/control_compare.py --form <форма>` — посмотреть дифф и
   `pair.png`.
5. Править модель (`FormWebModel.cpp`, `FormReader.cpp`) или рендерер
   (`resources/formpreview/js/form-preview.js`, `qv8-host.css`) до
   структурного нуля, затем `--update-baseline`.

## Текущее состояние (M0)

Формы фикстуры: `ПоляВвода`, `Надписи`, `Группы`. Эталоны сняты, сверка
работает; первые расхождения уже показывают разницу архитектуры, а не
пикселей:

- **Панель команд обработки.** Платформа рисует у формы обработки пустую
  командную панель с кнопкой «Ещё», наш рендер рисует полосу заголовка
  «Контролы управляемых форм» и не показывает «Ещё» — полоса 5…17 px.
- **Числовое поле.** В конфигураторе у него видны значение 0 и кнопки
  увеличения/уменьшения, у нас — нет.
- **Маска даты.** В конфигураторе в пустом поле даты стоят точки-разделители,
  у нас их нет (хотя на форме «Авансового отчёта» маска работает — значит,
  дело в типе реквизита формы).
- **Вертикальный ритм строк** расходится на 1–2 px из-за полосы заголовка.

Цифры текущего замера — в `out/control/control-report.md` (в репозиторий не
коммитится).

## Ограничения

- Захват эталонов требует интерактивного сеанса Windows с конфигуратором;
  1С-независимый гейт (`control_fixture_check.py`) работает где угодно.
- Эталоны зависят от платформы: версия записана в `refs/manifest.json`.
- Данные в контейнере беднее выгрузки, поэтому «полное совпадение» по
  свойствам возможно только у фикстуры, которую мы сами задаём.
