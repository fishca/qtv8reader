# qtv8reader v0.8.0

**23 ноября 2026**

0.8.0 доводит «точный вид» управляемых форм до эталона конфигуратора: свойства
элементов теперь разбираются из самой бинарной формы, а не угадываются по
метаданным. Вид контрола, видимость, заголовки и подсказки, размеры, свойства
полей, колонок и таблиц, настройки динамических списков, ориентация групп,
группы колонок, картинки и стили, команды кнопок — всё это сверено с выгрузкой
`Form.xml` по корпусу из 26 форм конфигурации.

## Главное

- **Свойства элементов — из формы, а не из догадок.** Платформа пишет
  в `Form.xml` только то, что отличается от значения по умолчанию, и бинарная
  форма устроена так же: свойство — это признак «слот не равен коду умолчания».
  Разобраны свойства полей, колонок, таблиц, групп, групп колонок, декораций,
  кнопок и динамических списков — совпадение с `Form.xml` по всему корпусу.
- **Вид контрола берётся из формы** (16 видов: надпись, поле ввода, флажок,
  картинка, переключатель, табличный документ, текстовый документ, календарь,
  индикатор, полоса прокрутки, диаграмма, граф, HTML-документ, форматированный
  документ, планировщик, PDF). Раньше вид выводился из типа реквизита, поэтому
  «Способ установки курса» был полем, а «Выполнена» — строкой.
- **Скрытые элементы больше не рисуются**, а подписи кнопок берутся из команд
  (292 из 294), подсказки — у всех видов элементов, а не только у полей.
- **Картинки и оформление**: общие картинки конфигурации, платформенные
  `StdPicture.*` и встроенные в форму картинки, цвета и шрифты из стилей —
  в модели появились значки важности и остановки в списке задач, картинки
  баннеров и крестиков закрытия, фон и шрифт надписей.
- **В модели формы 1627 элементов из 1645 эталонных** (было 1365): расхождение
  — 17 кнопок панели форматированного документа, которые рендерер строит сам,
  и одно дополнение поиска, которое платформа переносит в панель при выгрузке.

## Точный вид формы

### Вид контрола, заголовки и подсказки

- Вид элемента записан целым кодом непосредственно перед именем: 1 — надпись,
  2 — поле ввода, 3 — флажок, 4 — картинка, 5 — переключатель, 6 — табличный
  документ, 7 — текстовый документ, 8 — календарь, 9 — индикатор, 10 — полоса
  прокрутки, 11 — диаграмма, 14 — граф, 15 — HTML-документ, 17 —
  форматированный документ, 19 — планировщик, 20 — PDF. Сверено по `id`
  элемента: 560 полей 26 форм совпали на 100 %.
- Заголовок и подсказка поля читаются со своих мест в записи элемента
  (`+3` — `Title`, `+4` — `ToolTip`), а не берутся из первого локализованного
  текста: поле без заголовка больше не подписывается длинным текстом подсказки.
  Сверено по 561 полю — заголовки совпали во всех.
- Подсказки разбираются у групп, страниц, таблиц, декораций, кнопок и командных
  панелей — 177 подсказок корпуса совпали с `Form.xml`.
- Видимость: у групп, декораций и кнопок признак лежит в «хвосте» записи
  элемента, у полей — со смещением `+37`. Сверено побайтово по корпусу форм,
  включая формы с сотнями скрытых элементов.
- Подписи стандартных реквизитов зависят от вида объекта: код `-2` — «Код»
  у справочников и «Номер» у документов, код `-3` — «Наименование» и «Дата».
- Подписи переключателей берутся из списка выбора самой формы
  (`ChoiceListItems`) — «вводится вручную», «загружается из Интернета» вместо
  заглушек «<Значение 1>».

### Свойства полей и колонок

Смещения от индекса имени и коды значений сверены с `Form.xml` по 372
колонкам и 233 полям корпуса:

| Смещение | Свойство | Значения |
|---|---|---|
| +1 | `TitleLocation` | 0 None, 1 Auto, 2 Left, 3 Top, 4 Right, 5 Bottom |
| +8 | `ReadOnly` | 1 — true |
| +9 | `SkipOnInput` | 0/1 — false/true; 2 — по умолчанию |
| +10 | `DefaultItem` | 1 — true |
| +14 | `ShowInHeader` | 0 — false (по умолчанию true) |
| +15 | `ShowInFooter` | 0 — false (по умолчанию true) |
| +16 | `CellHyperlink` | 1 — true |
| +17 | `HorizontalAlign` | 0 Left, 1 Center, 2 Right; 3 — Auto |
| +18 | `HeaderHorizontalAlign` | 1 Center, 2 Right |
| +19 | `FooterHorizontalAlign` | 0 Left, 1 Center, 2 Right; 3 — Auto |
| +20 | `EditMode` | 0 Directly, 2 EnterOnInput; 1 — Auto |
| +21 | `VerticalAlign` | 0 Top, 1 Center, 2 Bottom; 3 — Auto |
| +22 | `AutoCellHeight` | 1 — true |
| +37 | `Visible` | 0 — false |
| +43 | `FixingInTable` | 1 Left, 2 Right |
| +44 | `ToolTipRepresentation` | 3 Button, 5 ShowTop, 7 ShowBottom |

Подсказка ввода (`InputHint`) лежит в записи макета поля ввода (код 36) сорок
пятым полем. Из записи макета же читаются размеры, растяжение и остальные
свойства поля ввода: `Wrap`, `ChoiceListButton`, `ChoiceButton`, `ClearButton`,
`SpinButton`, `OpenButton`, `ListChoiceMode`, `ChoiceListHeight`,
`DropListWidth`, `ChoiceFoldersAndItems`, `AutoChoiceIncomplete`,
`AutoMarkIncomplete`, `ChooseType`, `TextEdit`, `ChoiceButtonRepresentation`,
`DropListButton`, `ChoiceHistoryOnInput`, `AutoMaxWidth`, `MaxWidth`,
`AutoMaxHeight`; у поля-картинки — `Hyperlink` и `FileDragMode`. Все значения
по умолчанию сверены с `Form.xml` по 326 полям ввода и 56 полям-картинкам.

Размеры элементов тоже читаются со своих мест: у декорации ширина и высота
лежат через 4 и 5 полей после имени, у поля — в записи макета, код которой свой
у каждого вида контрола (36 — поле ввода, 11 — надпись и флажок, 10 —
поле-картинка, 6 — календарь); если второй элемент записи — список формата,
размеры идут со сдвигом на один. Поэтому поля календаря, полей-картинок и
декорации получают заданную в конфигураторе ширину, а поля больше не
растягиваются на всю форму.

### Таблицы и динамические списки

- Свойства таблицы (код 55): `TitleLocation`, `CommandBarLocation`, `Header`,
  `UseAlternationRowColor`, `AutoInsertNewRow`, `EnableStartDrag`, `EnableDrag`.
  «Автодобавление» и «чередование» попадают в модель только для true, как
  в `Form.xml`. Сверено по 48 таблицам корпуса.
- Настройки динамического списка записаны в записи таблицы блоком
  «количество, код, значение, …»: `AutoRefresh`, `AutoRefreshPeriod`, `Period`,
  `ChoiceFoldersAndItems`, `RestoreCurrentRow`, `TopLevelParent`, `ShowRoot`,
  `AllowRootChoice`, `RowFilter`, `UpdateOnDataChange`. Коды сверены с
  `Form.xml` по 87 таблицам динамических списков.
- Колонки динамических списков адресуются номером поля (`Список.#5`), а карта
  «номер → имя» лежит в настройках реквизита формы (`FieldsMapItemIdN` /
  `FieldsMapItemNameN`): колонка получает настоящее имя, заголовок и формат
  из метаданных. Реквизит списка помечается главным и отдаёт рендереру вид
  `cfg:DynamicList`, основную таблицу и текст запроса.
- Колонки таблиц значений и списков значений, объявленных реквизитами формы,
  получают настоящие имена из описания реквизита (`{5, номер, 0, имя, синоним,
  образец значения}`), а у списка значений состав задан платформой
  (`Value`/`Presentation`/`Check`). Совпадение путей к данным с `Form.xml`
  по корпусу выросло с 69,3 % до 73,2 %.

### Группы, группы колонок и декорации

- `Group` обычной группы выводится из режима ориентации в узле макета:
  0 — вертикально, 1 — горизонтально, 3 — всегда горизонтально, 2 —
  «горизонтально, если помещается» (умолчание, в `Form.xml` не пишется).
  Раньше `AlwaysHorizontal` подменялся на `Horizontal`, а значение по
  умолчанию попадало в модель лишним свойством. Сверено по 161 группе.
- Узел макета группы бывает записан и кодом 28, и кодом 29 — у таких групп
  больше не теряется ориентация.
- Группа колонок таблицы (код 22 с видом группы 2) хранит свои свойства
  в записи `{2, …}`: вид группировки (0 — `Horizontal`, 2 — `InCell`),
  показ заголовка и закрепление (`FixingInTable`). Рендерер без свойства
  считает группу вертикальной, поэтому `Horizontal` отдаётся явно. Сверено
  по 75 группам колонок корпуса и по 24 формам конфигурации (33 группы).
- Декорации: вид (надпись или картинка), признак гиперссылки и картинка
  читаются из записи оформления — сверено по 112 декорациям. Поэтому
  «Параметры прописи валюты» стали гиперссылкой, а крестики закрытия
  баннеров — картинками `StdPicture.InputFieldClear`.

### Картинки, цвета и шрифты

- Ссылка на общую картинку конфигурации записана GUID-ом, на стандартную
  картинку платформы — GUID-ом библиотеки платформы или отрицательным кодом,
  встроенная в форму картинка — base64 BMP в записи элемента. В модель они
  уходят узлом `commonPictures`; разобраны `ValuesPicture` поля,
  `HeaderPicture` колонки, `Picture` декорации и кнопки, встроенные картинки.
- Цвета и шрифты: ссылка на общий стиль — GUID, на стиль платформы —
  отрицательный код, цвет — абсолютное число или web-цвет. Сверено с
  `Form.xml` по 26 формам: `TextColor`, `TitleTextColor`, `BackColor`,
  `BorderColor`, `FontSpec`, `TitleFontSpec` совпали во всех 147 элементах.

### Командные панели и кнопки

- Кнопка ссылается на команду парой «номер, GUID»: стандартная команда формы,
  команда формы (номер — идентификатор в коллекции, а не позиция) или
  стандартная команда элемента. Восстановлено 292 из 294 кнопок корпуса,
  включая подписи «Записать и закрыть» и «Создать группу».
- Коды вида группы были перепутаны: 0 — своя командная панель формы,
  9 — панель автозаполнения. Теперь своя панель остаётся в дереве узлом
  `CommandBar`, панель автозаполнения уходит в `autoCommandBar`, а кнопки
  записи не дублируются. Расхождений тегов в модели — 45 → 0.
- Командная панель формы собирается из кнопок самой формы; лишние
  синтетические кнопки у списков, отчётов и обработок убраны, у основной
  таблицы списка больше нет собственной панели. «Создать на основании»
  добавляется только формам документов.
- Дополнения панели — строка поиска и состояние просмотра — отдаются
  рендереру: в форме списка появились поле «Поиск (Ctrl+F)» и состояние
  просмотра.
- Панель форматированного документа связывается с полем через
  `CommandSource`, и рендерер собирает её кнопки (шрифт, начертание,
  выравнивание, цвет) как в конфигураторе.

## Командная строка

- `v8reader_cli form-model <файл> <объект> [--form <имя>] [-o <файл>]` —
  JSON-модель формы для рендерера; `--items` печатает дерево элементов,
  а новый `--nodes` — отладочный дамп узлов формы в порядке сериализации
  (по нему сверялось расположение свойств с `Form.xml`).

Подробности разбора — в [docs/form-exact-view.md](docs/form-exact-view.md).

## Проверено

- Сверка с `Form.xml` по корпусу из 26 форм: 1645 элементов (теги совпадают
  у всех), 1387 групп, 372 колонки, 233 поля, 326 полей ввода, 56
  полей-картинок, 48 таблиц, 87 динамических списков, 161 группа, 75 групп
  колонок, 112 декораций, 294 кнопки, 177 подсказок, 147 элементов со стилями —
  расхождений нет. Дополнительно 24 формы конфигурации вне корпуса: 33 группы
  колонок, все три свойства совпали.
- 108 автотестов (88 ядра, 9 CLI, 11 GUI), `ctest`: 3/3.
- Изменения: 29 файлов, +6312 / −372 строки.
- Сборка MSYS2/MinGW-w64 (GCC 16, Qt 6, Release); сборка Linux
  (`#ifdef Q_OS_WIN`) — точный вид отключается на уровне кода.

## Ограничения

- Проект работает только на чтение; исполнение модулей и форм не
  поддерживается. Просматриваются управляемые формы (8.2/8.3/BAS); обычные
  формы 8.1/8.2 не поддерживаются.
- Не разбираются: форматированные заголовки `TitleFormatted` (100 элементов),
  ориентация страниц (9), оформление таблиц (`SearchStringLocation`,
  `SearchControlLocation`, `ViewStatusLocation`, `FileDragMode` — 31–42),
  `ExcludedCommands` (17), `AllowGettingCurrentRowURL` (17), `InitialTreeView`
  (6), `ExtendedEditMultipleValues` (34), `AutoMaxWidth` у полей-надписей (15)
  и таблиц (4), картинка строки таблицы `RowPictureDataPath` (12), ширина части
  колонок (32), выравнивание элементов в группе (`HorizontalAlign` 36,
  `GroupVerticalAlign` 29). Расхождения локальные и перечислены
  в [docs/form-exact-view.md](docs/form-exact-view.md).
- Точный вид доступен только в Windows-сборке: на Linux и без WebView2
  остаётся упрощённый рендерер.

`qtv8reader-v0.8.0-windows-x86_64.zip` — портативная сборка, Qt и все
